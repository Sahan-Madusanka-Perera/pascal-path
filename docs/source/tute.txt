1     Introduction to Pascal Programming
Pascal is a structured programming language created by Niklaus Wirth in 1970. It’s
named after the French mathematician Blaise Pascal.


1.1       Why Learn Pascal?
    • Uses simple, English-like words (begin, end, if, then)

    • Teaches you to think logically

    • Errors are easy to spot and fix

    • Foundation for learning other languages like C, C++, Java

    1.2       Basic Structure of a Pascal Program
    Every Pascal program follows this structure:
1   program ProgramName ;
2   { This is where you declare variables }
3   var
4       variableName : dataType ;
5

6   { This is where your actual code goes }
7   begin
8       { Your statements here }
9   end .


          Example
        Your First Pascal Program - Hello World
    1   program HelloWorld ;
    2   begin
    3       writeln ( ’ Hello , World ! ’) ;
    4       writeln ( ’ Welcome to Pascal Programming ! ’) ;
    5   end .

        Output:
        Hello, World!
        Welcome to Pascal Programming!

        Tip

        Notice the period (.) at the very end after end. This tells Pascal ”the program is
        complete”. Forgetting this period is a common mistake!



    2       Identifiers
    An identifier is simply a name you give to things in your program.
       Think of it like naming your pet. You could name your dog ”Buddy” or ”Max”.
    Similarly, you name variables in your program.


    2.1       What Can Have Identifiers?
        • Variables - Storage boxes for values that can change

        • Constants - Storage boxes for values that never change

                                                2
    • Programs - The name of your entire program

    • Procedures and Functions - Reusable blocks of code (advanced topic)


2.2       Rules for Creating Identifiers
    1. Must start with a letter (A-Z or a-z)

    2. After the first letter, you can use letters, numbers, or underscore ( )

    3. Cannot use spaces

    4. Cannot use reserved words (words Pascal already uses)

    5. No special symbols like @, #, $, %, &, *, -, +

    6. Pascal is NOT case-sensitive (Total = total = TOTAL)


2.3       Valid vs Invalid Identifiers

      Identifier                Valid?              Reason
      studentName               Valid               Starts with letter, no spaces
      student age               Valid               Underscore is allowed
      marks2023                 Valid               Numbers allowed after first letter
      TotalMarks                Valid               Perfectly fine
      9thGrade                  Invalid             Starts with number
      student name              Invalid             Contains space
      total-marks               Invalid             Hyphen not allowed
      begin                     Invalid             Reserved word
      student#                  Invalid             Special symbol # not allowed
       privateVar               Invalid             Cannot start with underscore

     Example
    Good Identifier Names:
1   var
2      studentAge : integer ;
3      averageMarks : real ;
4      studentName : string ;
5      isPassed : boolean ;
6      grade_A_count : integer ;

4      Standard Data Types
A data type tells Pascal what kind of value a variable can hold. It’s like saying ”this
box can only hold toys” or ”this box can only hold books”.


4.1        Integer Type
Stores whole numbers (positive, negative, or zero).

     Example
1    var
2      age : integer ;
3      temperature : integer ;
4      numberOfStudents : integer ;
5

6    begin
7      age := 16;
8      temperature := -5;
9      numberOfStudents := 450;
10

11     writeln ( ’ Age : ’, age ) ;
12     writeln ( ’ Temperature : ’, temperature ) ;
13     writeln ( ’ Students : ’, numberOfStudents ) ;
14   end .

     Output:
     Age: 16
     Temperature: -5
     Students: 450

     Tip

     Integer range: approximately -32,768 to 32,767 (in standard Pascal)
     For larger numbers, some Pascal versions offer longint


4.2        Real Type
Stores decimal numbers (numbers with fractional parts).




                                            5
     Example
1    var
2      height : real ;
3      average : real ;
4      price : real ;
5

6    begin
7      height := 5.8;
8      average := 87.5;
9      price := 1250.75;
10

11     writeln ( ’ Height : ’, height :0:2 , ’ feet ’) ;
12     writeln ( ’ Average : ’, average :0:1 , ’% ’) ;
13     writeln ( ’ Price : Rs . ’, price :0:2) ;
14   end .

     Output:
     Height: 5.80 feet
     Average: 87.5%
     Price: Rs. 1250.75

     Tip
     The notation :0:2 means ”use 0 total width and 2 decimal places”. This formats

    15       Arrays (One-Dimensional Arrays)
    In programming, we use variables to store data in memory. But what if we want to
    store many values of the same data type?
        For example, if you want to store marks of 35 students, writing 35 variable names like
    this is not practical:
1   var m1 , m2 , m3 , ... : integer ;           { BAD idea for many values }


       Tip

       When you have many items of the same type (like marks, ages, prices), use an
       array. It saves time and keeps your program clean.


    15.1     Why Use Arrays? (Use of Arrays)
    An array stores many values using one identifier name, and each value is accessed by
    an index.




                                               37
          Example
        Train Analogy:
        Imagine a train:

           • The train name = array name (example: marks)

           • Each cart = an element (one data item)

           • Cart number = index (0,1,2,...)

        So marks[0] is the first cart, marks[1] is the second, etc.


    15.2      Defining a One-Dimensional Array
    Correct Pascal syntax:
1   var
2       arrayName : array [ firstIndex .. lastIndex ] of dataType ;


          Example
        Example: Array for 10 integer marks
    1   var
    2      marks : array [0..9] of integer ;

        This creates 10 elements: marks[0] to marks[9].

        Common Mistake
        Many students write wrong syntax like marks ( array[0..9] of integer; That
        is incorrect in Pascal.
        Correct form is: marks : array[0..9] of integer;


    15.3      Important Attributes of an Array
        • Elements are stored sequentially (next to each other in memory).

        • Each element has an index written inside square brackets.

        • All values must be of the same data type.

        • You can access any element directly (random access): marks[7] is allowed anytime.

        • Arrays work perfectly with loops (for, while, repeat).



                                                38
     Example
     Array size depends on index range:
1    var
2      A : array [0..4] of integer ;          { size = 5 elements }
3      B : array [1..5] of integer ;          { size = 5 elements }

     Both arrays have 5 elements, but indexes are different.

17         Evolution of Programming Languages
A computer needs instructions to do tasks. A program is a sequence of instructions
written to solve a problem.
   But computers do not naturally understand English. They understand only machine-


                                          45
level instructions. That is why programming languages evolved.


17.1     Low-Level Languages
17.1.1   Machine Language

Machine language is written in binary (0 and 1). The CPU can execute it directly.

   • Fast

   • No translator needed

   • Very hard for humans

   • Machine dependent (one computer’s machine code may not run on another)

17.1.2   Assembly Language

Assembly uses symbols / mnemonics instead of 0 and 1 (like MOV, ADD).

   • Easier than machine language

   • Needs an assembler to translate into machine code

   • Still machine dependent

   Example
  Translation idea:
  Assembly program → Assembler → Machine code


17.2     High-Level Languages
High-level languages use more human-friendly words and structure.
   Examples: FORTRAN, BASIC, COBOL, PASCAL, C

   • Easier to read and write

   • Usually machine independent

   • Must be translated to machine code before running

  Tip

  Pascal is a high-level language and is excellent for learning structured / proce-
  dural programming.

18       Programming Paradigms (Types of Programming)
Different languages follow different approaches to solving problems. These approaches
are called paradigms.


18.1     Procedural vs Declarative
18.1.1   Procedural Paradigm (How to do it)

Procedural programming explains step-by-step how to solve a problem. It uses state-
ments like if, for, while, procedures, etc.

     Example
  Procedural idea:
  “First do this, then do that, then finish.”
  Pascal is mainly procedural.


18.1.2   Declarative Paradigm (What you want)

Declarative programming describes what result you want, not the step-by-step method.
The system decides how to achieve it.

     Example
  Declarative idea:
  “I want students with marks > 75” (and the system finds them).
  Common in AI and database thinking.

  Common Mistake
  Do not confuse these:

       • Procedural: how to achieve it

       • Declarative: what you want


18.2     Structured vs Object-Oriented
18.2.1   Structured Programming

Structured programming focuses on breaking a system into functions/processes and
uses a top-down approach.
   Typical flow:

   • Input

                                           47
   • Process

   • Output

   Pascal supports structured programming strongly.

18.2.2    Object-Oriented Programming (OOP)

OOP is based on objects. An object has:

   • Data (attributes / properties)

   • Methods (actions / procedures that work on data)

     Example

  Activity (Exam-friendly): Car as a Class
  Class: Car
  Properties: color, brand, speed, fuelLevel
  Methods: start(), stop(), accelerate(), brake()
  Objects: ToyotaCar, BMWCar, HondaCar


18.3     Programming vs Scripting
Programming languages often require compilation and have strict structure. Script-
ing languages are often interpreted and frequently used for automating tasks.

     Example
  Examples:

       • Programming: Pascal, C, C++

       • Scripting: JavaScript, PHP



19       Language Translators (Assembler, Interpreter, Com-
         piler)
Most languages (except machine language) need translation into machine code.


19.1     Assembler
Converts assembly language into machine code.



                                          48
   Example
  Assembly → Assembler → Machine code


19.2     Interpreter
An interpreter translates and executes the program line by line.

   • Executes step-by-step

   • If an error occurs, it stops at that line (can run until the error line)

   • Translation happens every time you run the program

  Tip
  Interpreters are great for learning because you can quickly test small parts.


19.3     Compiler
A compiler translates the entire program at once into machine code (before running).

   • If there are errors, the compilation fails and the program does not run

   • If there are no errors, you get machine code/executable output

   • After compiling once, you can run many times without translating again (unless
     source code changes)

   Example
  High-level program → Compiler → Machine code
  Then you run the machine code many times.

  Common Mistake
  Key difference (must know for exams):

       • Interpreter: translates statement by statement

       • Compiler: translates whole program at once
